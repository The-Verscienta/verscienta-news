# Feature Flags Design

> **Historical — standalone Verscienta app.** This file describes `Verscienta.*` LiveView work. It is not the Kiln overlay and it is not Slice 1. Current scope is [`docs/slice-1.md`](../../slice-1.md).


**Date:** 2026-06-04
**Status:** Approved
**Phase:** 2 — Social & Gamification (cross-cutting)
**Depends on:** Phase 0; Accounts (`User`, `role`); Communities (`GroupMembership`); Oban (for the cron gates); Phoenix.PubSub; existing `:admin` pipeline.

## Goal

Install [FunWithFlags](https://hex.pm/packages/fun_with_flags) with Postgres persistence + ETS cache, wrap it behind a thin `Verscienta.Flags` module with a hard-coded allowlist of known flags, gate 7 existing features for kill-switch insurance, seed 6 disabled Phase-3 placeholders, and ship a Codex-styled admin LiveView for managing all four FunWithFlags dimensions (boolean / actor / group / percentage) with an audit trail.

## Decisions

| Decision | Choice |
|----------|--------|
| Library | `fun_with_flags ~> 1.12` |
| Persistence | Postgres via FunWithFlags' Ecto adapter (reuses `Verscienta.Repo`) |
| Cache | ETS (in-process), with Phoenix.PubSub invalidation hook ready for multi-node |
| Public API | New `Verscienta.Flags` module with `@known_flags` allowlist |
| Actor impl | `FunWithFlags.Actor` for `Verscienta.Accounts.User` → id `"user:<uuid>"` |
| Group impl | `FunWithFlags.Group` for User — role-based (`:admins, :experts, :moderators`) and membership-based (`:group_member_<group_id>`) |
| Gate mechanism | Per-route plug `VerscientaWeb.Plugs.Gate` + inline `Flags.enabled?/2` for workers/business logic |
| Off-route UX | Renders `ComingSoonLive` (preserves URL, no redirect) |
| Admin bypass | If `current_user.role == :admin`, gate passes through with `flag_force_visible: true` so the LV can render an "admin-only preview" banner |
| Admin UI | Custom Codex LiveView at `/admin/flags` + drill-down at `/admin/flags/:name` |
| Retroactive gates | 7 flags default ON: `reward_store, referrals, quests, leaderboards, communities, reposts, ai_enrichment` |
| Phase 3 seeds | 6 flags default OFF: `for_you_feed, live_rooms, digest_emails, auto_moderation, expert_program, writing_assistant` |
| Audit | New `feature_flag_audit` table — actor + flag + action + params + occurred_at |
| Test setup | `Verscienta.DataCase` auto-seeds flags so existing tests don't regress |

## Section 2: `Verscienta.Flags` wrapper + Actor/Group impls

### `Verscienta.Flags`

A thin wrapper so callers don't import `FunWithFlags` directly. Atom-typed flag names; raises on unknown flag (catches typos at the call site).

```elixir
defmodule Verscienta.Flags do
  @moduledoc "Public API for feature flag checks and toggles."

  @known_flags ~w(
    reward_store referrals
    quests leaderboards
    communities reposts
    ai_enrichment
    for_you_feed live_rooms
    digest_emails auto_moderation
    expert_program writing_assistant
  )a

  def known_flags, do: @known_flags

  def enabled?(flag, opts \\ [])

  def enabled?(flag, for: actor) when is_atom(flag),
    do: validate!(flag) && FunWithFlags.enabled?(flag, for: actor)

  def enabled?(flag, []) when is_atom(flag),
    do: validate!(flag) && FunWithFlags.enabled?(flag)

  def enable(flag, opts \\ []), do: validate!(flag) && do_enable(flag, opts)
  def disable(flag, opts \\ []), do: validate!(flag) && do_disable(flag, opts)
  def list, do: FunWithFlags.all_flags() |> elem(1)

  defp validate!(flag) do
    if flag in @known_flags, do: true,
       else: raise ArgumentError, "Unknown feature flag: #{inspect(flag)}. Add it to Verscienta.Flags.@known_flags."
  end

  defp do_enable(flag, []), do: FunWithFlags.enable(flag)
  defp do_enable(flag, for_actor: actor), do: FunWithFlags.enable(flag, for_actor: actor)
  defp do_enable(flag, for_group: group), do: FunWithFlags.enable(flag, for_group: group)
  defp do_enable(flag, for_percentage_of: {:actors, p}), do: FunWithFlags.enable(flag, for_percentage_of: {:actors, p})

  defp do_disable(flag, []), do: FunWithFlags.disable(flag)
  defp do_disable(flag, for_actor: actor), do: FunWithFlags.disable(flag, for_actor: actor)
  defp do_disable(flag, for_group: group), do: FunWithFlags.disable(flag, for_group: group)
end
```

### Actor impl

```elixir
defimpl FunWithFlags.Actor, for: Verscienta.Accounts.User do
  def id(%{id: id}), do: "user:#{id}"
end
```

The string `"user:<uuid>"` is what FunWithFlags hashes for percentage rollouts and stores per-actor toggles against.

### Group impl

```elixir
defimpl FunWithFlags.Group, for: Verscienta.Accounts.User do
  require Ash.Query
  alias Verscienta.Communities.GroupMembership

  def in?(%{role: role}, :admins),     do: role == :admin
  def in?(%{role: role}, :experts),    do: role == :expert
  def in?(%{role: role}, :moderators), do: role == :moderator

  def in?(%{id: user_id}, group_atom) when is_atom(group_atom) do
    case Atom.to_string(group_atom) do
      "group_member_" <> group_id ->
        GroupMembership
        |> Ash.Query.filter(user_id == ^user_id and group_id == ^group_id and status == :active)
        |> Ash.exists?(authorize?: false)

      _ -> false
    end
  end
end
```

Group atom convention:
- `:admins`, `:experts`, `:moderators` → role match.
- `:group_member_<group_uuid>` → active membership match. Admins can flip a flag for "members of community X" by toggling this group in the admin UI.

**Cost note.** Each `in?/2` for a group flag runs one query per request. Acceptable for v1; if it becomes hot, memoize in conn assigns.

## Section 3: Gate plug + Coming Soon LV

### `VerscientaWeb.Plugs.Gate`

```elixir
defmodule VerscientaWeb.Plugs.Gate do
  @moduledoc "Per-route feature-flag gate. `plug :gate, flag: :reward_store`."
  import Plug.Conn
  alias Verscienta.Flags

  def init(opts), do: opts

  def call(conn, opts) do
    flag = Keyword.fetch!(opts, :flag)
    user = conn.assigns[:current_user]

    enabled? =
      if user, do: Flags.enabled?(flag, for: user), else: Flags.enabled?(flag)

    cond do
      enabled? ->
        assign(conn, :active_flag, flag)

      bypass_for_admin?(conn) ->
        conn
        |> assign(:active_flag, flag)
        |> assign(:flag_force_visible, true)

      true ->
        conn
        |> assign(:flag_off_for, flag)
        |> Phoenix.LiveView.Controller.live_render(VerscientaWeb.ComingSoonLive,
             session: %{"flag" => Atom.to_string(flag)})
        |> halt()
    end
  end

  defp bypass_for_admin?(conn) do
    case conn.assigns[:current_user] do
      %{role: :admin} -> true
      _ -> false
    end
  end
end
```

**Three branches:**
1. **Flag on** → `:active_flag` assigned, pass through.
2. **Flag off, admin viewer** → `:flag_force_visible: true`, pass through. Downstream LV/template shows a "🚧 Admin preview — gated off for non-admins" banner.
3. **Flag off, non-admin** → render Coming Soon LV at the same URL (no redirect; preserves shareability for admins). `halt/1` stops the plug pipeline.

### `VerscientaWeb.ComingSoonLive`

```elixir
defmodule VerscientaWeb.ComingSoonLive do
  use VerscientaWeb, :live_view

  @impl true
  def mount(_params, %{"flag" => flag}, socket),
    do: {:ok, assign(socket, flag: flag, page_title: "coming soon")}
end
```

Template (Codex tokens, lowercase title):
```heex
<div class="mx-auto max-w-xl p-8 text-center space-y-4">
  <h1 class="text-3xl font-bold lowercase text-ink">Coming soon</h1>
  <p class="text-ink-3"><%= human_label(@flag) %> isn't available yet. Check back later.</p>
  <p class="text-xs text-ink-3">
    <.link navigate={~p"/"} class="underline">Back to the front page →</.link>
  </p>
</div>
```

`human_label/1` looks up `Verscienta.Flags.Seeds.labels()[String.to_existing_atom(flag)]` with a fallback that replaces underscores with spaces.

**Admin bypass banner** — a `<.flag_admin_banner flag={@active_flag} force_visible={@flag_force_visible} />` component rendered conditionally in the root layout. Renders nothing unless `force_visible == true`.

## Section 4: Admin LVs

### `/admin/flags` — index (`AdminFlagsLive`)

- **Loads** all flags via `Flags.list/0`, partitions into "Retroactive (existing features)" and "Phase 3 placeholders" using `Flags.Seeds` lists.
- **Renders** one table per group with columns: flag name, summary state, last-changed-at (read directly from `fun_with_flags_toggles`), quick toggle button.
- **Summary state** — one line covering active dimensions: `Boolean: on/off · Actors: 3 · Groups: admins, experts · Rollout: 25%`. Empty axes omitted.
- **Quick toggle** — flips the boolean gate; goes through the audit logging path (Section 5).
- **PubSub** — subscribes to `"flags"` topic; show page broadcasts after every change so the index updates live.

### `/admin/flags/:name` — drill-down (`AdminFlagShowLive`)

Four panels, one per FunWithFlags dimension. Each panel submits independently and writes to the audit log.

**1. Boolean global** — Off / On toggle.

**2. Actor overrides** — list of `user:<id>` entries with remove buttons. "Add user override" form: username input → resolves to User → choose on/off → submit. Inline error on unknown username.

**3. Group overrides** — three-state cycle (unset / on / off) for predefined groups `:admins`, `:experts`, `:moderators`. "Add community group" form accepts a Group slug or id, stored as `:group_member_<id>`. Remove ✕ per row.

**4. Percentage rollout** — slider 0–100 in 5% steps. "Clear rollout" button. Below the slider: `"Roughly N of M active users would be on this rollout"` — `User` count cached in the LV process for 5 minutes.

**Confirmation modal** — on actions that would *disable* a retroactive flag (anything in `Seeds.retroactive_on()`). Phase-3 placeholders skip the confirm.

**Authorization** — `:admin` pipeline gates routes; in addition, all panel controls disable themselves if `current_user.role != :admin` (defense in depth).

**Audit display** — `<details>` block under the panels showing the most-recent-20 audit rows for this flag (actor username + action + timestamp).

### Audit resource

`Verscienta.Flags.Audit`:
- `id` uuid pk
- `belongs_to :actor_user, Verscienta.Accounts.User, allow_nil?: true` (nullable for system seeds)
- `flag_name` — `:string`, not null
- `action` — `:atom`, one_of `[:enable, :disable, :set_percentage, :clear_percentage, :add_actor, :remove_actor, :add_group, :remove_group]`
- `params` — `:map`, default `%{}` (action-specific context, e.g. `%{"percentage" => 25}`, `%{"actor" => "user:abc"}`)
- `occurred_at` — `:utc_datetime_usec`
- index `(flag_name, occurred_at desc)`

Writes are best-effort — a failed audit insert doesn't roll back the flag change. (Audit is a read-side aid, not a transactional guarantee.)

## Section 5: Seeds, retroactive integration, testing

### Seeds

`Verscienta.Flags.Seeds.seed!/0`:
- For each flag in `@retroactive_on`, enable the boolean gate if not already set.
- For each flag in `@phase3_off`, materialize a row by enable-then-disable if no row exists (so the admin UI lists it as "Off" rather than as "Unknown").
- Idempotent: re-running produces no changes.

`mix verscienta.flags.seed` wraps it.

### Retroactive integration sites

**HTTP routes** — `plug :gate, flag: :NAME` per route:
- `/store`, `/store/history` → `:reward_store`
- `/settings/referrals`, `/r/:code` → `:referrals`
- `/quests` → `:quests`
- `/leaderboard` → `:leaderboards`
- `/groups`, `/groups/new`, `/groups/:slug`, `/groups/:slug/manage`, `/groups/:slug/settings` → `:communities`

**Cron workers** — guard `perform/1`:
- `QuestAssignerWorker`, `FreezeRefillWorker` → `:quests`
- `LeaderboardSnapshotWorker` → `:leaderboards`
- `EnrichArticleWorker` → `:ai_enrichment`
- `AnomalyScanWorker` — no gate (safety mechanism)

**Ingest hooks** — inline:
- `Content.Article.changes.enqueue_enrich` skip-enqueue if `:ai_enrichment` off
- `auth_controller.ex` referral capture skip if `:referrals` off

**Button/component visibility** — render-time check:
- "Repost" button → `:reposts`
- "Create group" button → `:communities`

**Pattern for workers:**
```elixir
@impl Oban.Worker
def perform(%Oban.Job{} = job) do
  if Verscienta.Flags.enabled?(:quests) do
    do_perform(job)
  else
    :ok
  end
end
```

### Testing

**`Verscienta.Flags` tests** (`test/verscienta/flags_test.exs`):
- `enabled?/1` returns true for a globally-enabled flag.
- `enabled?/2 for: user` honors actor overrides.
- `enabled?/2 for: user` honors `:admins` group.
- `enabled?/2 for: user` honors `:group_member_<id>` after joining a Group.
- `enabled?/1` on an unknown flag raises `ArgumentError`.
- `list/0` includes all known flags after `Seeds.seed!/0`.

**Gate plug tests** (`test/verscienta_web/plugs/gate_test.exs`):
- Flag on → pass through with `:active_flag` assigned.
- Flag off, non-admin → Coming Soon LV rendered, status 200.
- Flag off, admin → pass through with `:flag_force_visible: true`.

**Audit tests** (`test/verscienta/flags/audit_test.exs`):
- Every flag-mutating API call writes one audit row.
- Audit row captures actor, flag, action, params.
- Audit insert failure does not propagate (worker keeps running).

**Existing test regression** — retroactive gates default ON via seeds, but existing tests don't call seeds. To keep all existing tests passing without modification:

1. `test/test_helper.exs` calls `Verscienta.Flags.Seeds.seed!/0` ONCE before the Ecto sandbox starts. Seeded rows live in the persistent test DB, outside any test's sandbox transaction.
2. `Verscienta.DataCase`'s `setup` block adds `on_exit(fn -> FunWithFlags.clear_cache() end)` so per-test mutations don't leak via the ETS cache after the sandbox rolls them back.

This gives every test the seeded baseline (retroactive=on, phase3=off) without per-test DB overhead, and tests that mutate flags get isolation through the existing sandbox + cache clear.

**Tests that need a different baseline** — e.g. testing what happens when `:reward_store` is off — call `Flags.disable(:reward_store)` inside the test. The change is visible for the rest of that test (ETS cache + transaction), then rolled back + cache-cleared at test end.

**Gates** — existing CI: `mix compile --warnings-as-errors`, `mix format --check-formatted`, `mix credo --strict`, `mix test`, `mix dialyzer`. Migrations via `mix ash.codegen` + FunWithFlags' own migration helper.

## Out of scope (deferred)

- Per-flag descriptions/help text rendered in the admin UI (label map exists; rendering is polish).
- Group/actor diff history in the audit (we log the trigger, not before/after state).
- Per-flag scheduled enable/disable.
- Multi-region / per-environment flag state.
- A/B testing or experimentation framework (FunWithFlags is a gate, not a measurement system).
- Programmatic flag access via API (admin LV only).
- Caching the User-count for the rollout slider beyond per-LV-process memoization (cross-process Cachex/ETS is YAGNI for one slider).
- Phoenix.PubSub multi-node invalidation wiring (single-node today; FunWithFlags has hooks ready for when this becomes relevant).

## Definition of Done

- `Verscienta.Flags` is the only place app code calls flag APIs; `@known_flags` allowlist enforced at runtime.
- All 13 flags seeded idempotently via `mix verscienta.flags.seed`. Re-running the task is a no-op.
- 7 retroactive routes/workers gated; existing tests still pass without modification (auto-seed in DataCase).
- 6 Phase 3 placeholders ready to flip when those features land.
- Admin LVs at `/admin/flags` and `/admin/flags/:name` provide full control over all four dimensions, with an audit log per change.
- `:gate` plug short-circuits non-admin requests to Coming Soon LV; admin bypass with a banner on downstream pages.
- Coming Soon LV uses Codex tokens, matches existing LV style.
- `feature_flag_audit` table records who-changed-what-when.
- CI gates green (format, compile, credo, dialyzer).
- `mix verscienta.flags.seed` smokes cleanly against dev DB.
