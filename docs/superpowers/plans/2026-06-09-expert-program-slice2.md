# Expert Program Slice 2 (Byline Tags + Featured + Skip-Hold) — Implementation Plan

> **Historical — standalone Verscienta app.** This file describes `Verscienta.*` LiveView work. It is not the Kiln overlay and it is not Slice 1. Current scope is [`docs/slice-1.md`](../../slice-1.md).


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show an "Expert" tag on expert author/commenter bylines, let moderators feature articles (sorted first in feeds), and let expert-authored articles skip the AI moderation auto-hold.

**Architecture:** A reusable `expert_tag/1` component rendered on the article-reader byline + comment authors (role-driven). A `featured_until` attribute + mod `:set_featured_until` action + a `featured_now` calc on Article, with the feed reads sorting featured-first and a mod-only feature/unfeature control on the reader. A contained `AutoModerateWorker` change skips the article hold when the author is a verified expert.

**Tech Stack:** Elixir, Phoenix LiveView, Ash 3, AshPostgres.

**Spec:** `docs/superpowers/specs/2026-06-09-expert-program-slice2-design.md`

**Conventions:**
- All `mix` commands run in Docker: `docker compose exec app mix ...` (service `app`).
- Migrations autogenerated via `mix ash_postgres.generate_migrations`.
- Commit messages end with the `Co-Authored-By` trailer shown in each step.
- Branch: `phase-3-expert-program-slice2` (stacked on Slice 1). Each implementer should `git checkout phase-3-expert-program-slice2` first and STOP/report if the tree is dirty.

```elixir
defmodule Verscienta.Content.FeaturedTest do
  use Verscienta.DataCase, async: false

  alias Verscienta.Content.Article

  defp user(name, role \\ :user) do
    u =
      Verscienta.Accounts.User
      |> Ash.Changeset.for_create(:register_with_password, %{
        email: name <> "@example.com",
        username: name,
        password: "password123",
        password_confirmation: "password123"
      })
      |> Ash.create!(authorize?: false)

    if role == :user do
      u
    else
      u
      |> Ash.Changeset.for_update(:update_profile, %{}, actor: u)
      |> Ash.Changeset.force_change_attribute(:role, role)
      |> Ash.update!(authorize?: false)
    end
  end

  defp published(author, title) do
    art =
      Article
      |> Ash.Changeset.for_create(:create, %{title: title, blocks: [], category: :movement},
        actor: author
      )
      |> Ash.create!()

    art |> Ash.Changeset.for_update(:publish, %{}, actor: author) |> Ash.update!()
  end

  defp set_featured(art, until, actor) do
    art
    |> Ash.Changeset.for_update(:set_featured_until, %{featured_until: until}, actor: actor)
    |> Ash.update(actor: actor)
  end

  defp published_ids do
    Article |> Ash.read!(action: :list_published, authorize?: false) |> Enum.map(& &1.id)
  end

  test "a moderator can set featured_until; a non-mod cannot" do
    author = user("feat_author")
    mod = user("feat_mod", :moderator)
    art = published(author, "Featurable")
    until = DateTime.add(DateTime.utc_now(), 14, :day)

    assert {:error, _} = set_featured(art, until, author)
    assert {:ok, updated} = set_featured(art, until, mod)
    assert updated.featured_until == until
  end

  test "a currently-featured article sorts ahead of a newer non-featured one" do
    author = user("feat_author2")
    mod = user("feat_mod2", :moderator)

    older = published(author, "Older")
    newer = published(author, "Newer")

    # Without featuring, newest first.
    ids = published_ids()
    assert Enum.find_index(ids, &(&1 == newer.id)) < Enum.find_index(ids, &(&1 == older.id))

    # Feature the older one → it sorts first.
    {:ok, _} = set_featured(older, DateTime.add(DateTime.utc_now(), 14, :day), mod)
    ids2 = published_ids()
    assert Enum.find_index(ids2, &(&1 == older.id)) < Enum.find_index(ids2, &(&1 == newer.id))
  end

  test "an expired featured_until does not sort first" do
    author = user("feat_author3")
    mod = user("feat_mod3", :moderator)

    older = published(author, "Older3")
    newer = published(author, "Newer3")

    # featured_until in the PAST → not currently featured.
    {:ok, _} = set_featured(older, DateTime.add(DateTime.utc_now(), -1, :day), mod)

    ids = published_ids()
    assert Enum.find_index(ids, &(&1 == newer.id)) < Enum.find_index(ids, &(&1 == older.id))
  end
end
```

## Notes for the implementer

- **Bylines key off `user.role == :expert`** — no flag gate. The `author`/`comment.user` records are already loaded with their `role` attribute.
- **`featured_now` is a calculation** (`featured_until > now()`), not a column — so an expired `featured_until` correctly evaluates `false` and the article falls back to date order. Only the `featured_until` timestamp is a real column/migration.
- **Featured is general mod curation** (any published article, decoupled from `:expert_program`); the `:set_featured_until` action is mod/admin policy-gated, and the reader control + handler use an actor-authorized `Ash.update` so a crafted non-mod event is rejected.
- **Skip-hold is article-only and hold-only:** expert comments are still held, and dubious expert articles still escalate. The AI flag is always created (in `maybe_flag`, unchanged), so an expert's flagged article still appears in the mod queue for human review — it just isn't auto-hidden.
- **Out of scope (later):** expert tags on feed/listing cards, auto-featuring, an admin featuring dashboard, skipping escalate for experts.
