# Moderation Auto-Actions Slice 1 (Hold + Escalate + Audit) — Implementation Plan

> **Historical — standalone Verscienta app.** This file describes `Verscienta.*` LiveView work. It is not the Kiln overlay and it is not Slice 1. Current scope is [`docs/slice-1.md`](../../slice-1.md).


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the AI-detection pipeline take automated, reversible enforcement actions — **HOLD** (hide content pending review) and **ESCALATE** (raise a flag's queue priority) — plus give moderators the same actions manually, all recorded in the `Moderation.Action` audit log.

**Architecture:** Add a `moderation_status` (`:visible | :held`) field to comment/article/message with system `:hold`/`:unhold` actions, dispatched polymorphically via `Moderation.Subject`. Held content is filtered from every public read (feeds, search, recommendations, room messages) and shown as an "under review" placeholder in threads/reader. Add a `priority` (`:normal | :high`) field + `:escalate` action to `Flag`, ordered first in the queue. Extend `Moderation.Action` (new action types, nullable moderator, `automated?`). The `AutoModerateWorker` performs enforcement only when a new `:auto_enforcement` flag (default off) is on; resolving a flag lifts any hold.

**Tech Stack:** Elixir, Phoenix LiveView, Ash 3, AshPostgres, Oban, Meilisearch, FunWithFlags.

**Spec:** `docs/superpowers/specs/2026-06-09-moderation-auto-actions-slice1-design.md`

**Conventions:**
- All `mix` commands run in Docker: `docker compose exec app mix ...` (service `app`).
- Migrations are autogenerated from snapshots via `mix ash_postgres.generate_migrations` — do NOT hand-write them.
- Commit messages end with the `Co-Authored-By` trailer shown in each commit step.
- Branch: `phase-3-moderation-auto-actions` (already created). Each implementer should `git checkout phase-3-moderation-auto-actions` first and STOP/report if the tree is dirty from concurrent activity.

```elixir
  Record a system/automated moderation action (no moderator). Best-effort:
  returns :ok even if the write fails. `opts`: `:note`.
  """
  def record_auto_action(action, subject_type, subject_id, opts \\ []) do
    target_user_id =
      case Subject.snapshot(subject_type, subject_id) do
        {_excerpt, author_id} -> author_id
        :error -> nil
      end

    |> Ash.Changeset.for_create(:record, %{
      action: action,
      subject_type: subject_type,
      subject_id: subject_id,
      target_user_id: target_user_id,
      moderator_id: nil,

      occurred_at: DateTime.utc_now()
    })
    |> Ash.create(authorize?: false)
    |> case do
      {:ok, _} -> :ok
```

```elixir
  subject and record it in the audit log (`automated?: false`). Returns :ok.
  """
  def apply_manual_action(:hold, subject_type, subject_id, moderator) do
    Subject.hold(subject_type, subject_id)
    record_manual_action(:hold, subject_type, subject_id, moderator)
  end

  def apply_manual_action(:restore, subject_type, subject_id, moderator) do
    Subject.unhold(subject_type, subject_id)
    record_manual_action(:restore, subject_type, subject_id, moderator)
  end

  def apply_manual_action(:escalate, subject_type, subject_id, moderator) do
    escalate(subject_type, subject_id)
    record_manual_action(:escalate, subject_type, subject_id, moderator)
  end

  defp record_manual_action(action, subject_type, subject_id, moderator) do
    target_user_id =
      case Subject.snapshot(subject_type, subject_id) do
        {_excerpt, author_id} -> author_id
        :error -> nil
      end

    Action
    |> Ash.Changeset.for_create(:record, %{
      action: action,
      subject_type: subject_type,
      subject_id: subject_id,
      target_user_id: target_user_id,
      moderator_id: moderator.id,
      automated?: false,
      occurred_at: DateTime.utc_now()
    })
    |> Ash.create(authorize?: false)

    :ok
  end
```

## Notes for the implementer

- **`moderation_status` is `writable?: false`** — it is set only via the `:hold`/`:unhold` actions' `set_attribute` (which force-changes it), mirroring how `User.suspended_until` is set by `:suspend`/`:unsuspend`.
- **Held vs deleted vs archived** are orthogonal. Held is reversible and distinct from author/mod deletion. A held article keeps `status: :published`; it is hidden purely by the `moderation_status` filter, so unhold restores it without re-publishing.
- **Reversibility:** resolving a flag always lifts an auto-hold first, then applies the resolution's content fate (`content_removed` removes; everything else leaves the content visible). Suspension does not auto-remove content (unchanged behavior).
- **Two-flag gating:** detection (`:auto_moderation`) and enforcement (`:auto_enforcement`) are independent; both are off by default. Enforcement also requires that a flag was raised (the worker only enforces inside `maybe_flag`).
- **Graceful degradation:** every enforcement path is best-effort (`Subject.hold`, `escalate`, `record_auto_action`, and `maybe_enforce`'s rescue) — a failure never crashes the worker, fails the user's submit, or blocks flag creation.
- **Out of scope (Slice 2):** SHADOW (silent author-only visibility, viewer-aware filtering), auto-shadow for repeat offenders, author notifications on hold.
