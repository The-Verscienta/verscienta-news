# Digest Emails — Core + Unsubscribe Implementation Plan

> **Historical — standalone Verscienta app.** This file describes `Verscienta.*` LiveView work. It is not the Kiln overlay and it is not Slice 1. Current scope is [`docs/slice-1.md`](../../slice-1.md).


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Personalized For-You digest emails — opt-in preference, a per-user send worker, one-click unsubscribe, and a settings selector.

**Architecture:** `User.digest_frequency`/`last_digest_at` + actions; `Verscienta.Digests` (highlights + signed unsubscribe token); a Swoosh `Digests.Email`; `SendDigestWorker` (Oban, guards + deliver + record); a token-authed unsubscribe controller; a `SettingsLive` opt-in.

**Tech Stack:** Elixir, Ash 3, Oban, Swoosh (`Verscienta.Mailer`), `Phoenix.Token`, `Recommendations.for_you`. All `mix` runs in Docker: `docker compose exec -T app mix …`.

**Spec:** `docs/superpowers/specs/2026-06-05-digests-design.md`
**Branch:** `phase-3-digests` (spec already committed here).

**Confirmed facts:**
- Sender pattern (`lib/verscienta/accounts/user/senders/send_password_reset_email.ex`): `use VerscientaWeb, :verified_routes`; `import Swoosh.Email`; `new() |> from({"Verscienta News", "noreply@verscienta.news"}) |> to(to_string(user.email)) |> subject(...) |> html_body(...) |> Mailer.deliver!()`.
- Test mailer adapter is `Swoosh.Adapters.Test`; email tests use `import Swoosh.TestAssertions`, `setup :set_swoosh_global`, `async: false`, `assert_email_sent(fn email -> ... end)`.
- `Recommendations.for_you(user, opts)` returns `[%{type: :article, article: %Article{}, repost: nil, timestamp: …}]`.
- `User` has `:update_profile` (accept `[:username, :display_name, :bio, :avatar_url, :timezone, :flair, :equipped_theme]`) policied `authorize_if expr(id == ^actor(:id))`; `:update_notification_prefs`. `SettingsLive` builds an `AshPhoenix.Form` for `:update_profile` (`handle_event("save", %{"form" => params}, …)`).
- `:digest_emails` flag already in `Flags`. Oban queues: `default/aggregation/ai`.

```elixir
defmodule Verscienta.Digests do
  @moduledoc "Personalized digest content + unsubscribe tokens."
  use VerscientaWeb, :verified_routes

  alias Verscienta.Recommendations

  @highlight_limit 5
  @token_salt "digest unsubscribe"
  @token_max_age 2_592_000

  @doc "Up to 5 For-You articles published within the user's digest window; [] if none/off."
  def highlights(user) do
    days = window_days(user.digest_frequency)

    if days == 0 do
      []
    else
      cutoff = DateTime.add(DateTime.utc_now(), -days * 86_400, :second)

      user
      |> Recommendations.for_you(limit: 30)
      |> Enum.map(& &1.article)
      |> Enum.filter(fn a ->
        a.published_at && DateTime.compare(a.published_at, cutoff) != :lt
      end)
      |> Enum.take(@highlight_limit)
    end
  end

  def window_days(:weekly), do: 7
  def window_days(:daily), do: 1
  def window_days(_), do: 0

  @doc "A signed one-click unsubscribe token for `user`."
  def unsubscribe_token(user),
    do: Phoenix.Token.sign(VerscientaWeb.Endpoint, @token_salt, user.id)

  @doc "Verify an unsubscribe token → `{:ok, user_id} | {:error, reason}`."
  def verify_unsubscribe_token(token),
    do: Phoenix.Token.verify(VerscientaWeb.Endpoint, @token_salt, token, max_age: @token_max_age)
end
```

```elixir
defmodule Verscienta.Digests.Email do
  @moduledoc "Builds + delivers the personalized digest email."
  use VerscientaWeb, :verified_routes

  import Swoosh.Email

  alias Verscienta.{Digests, Mailer}

  def deliver(user, articles), do: user |> build(articles) |> Mailer.deliver()

  def build(user, articles) do
    new()
    |> from({"Verscienta News", "noreply@verscienta.news"})
    |> to(to_string(user.email))
    |> subject("Your Verscienta digest")
    |> html_body(html(user, articles))
    |> text_body(text(user, articles))
  end

  defp html(user, articles) do
    unsub = url(~p"/digests/unsubscribe/#{Digests.unsubscribe_token(user)}")

    items =
      Enum.map_join(articles, "", fn a ->
        ~s(<p><a href="#{url(~p"/articles/#{a.slug}")}">#{esc(a.title)}</a><br/>#{esc(a.excerpt || "")}</p>)
      end)

    """
    <h1>Your Verscienta digest</h1>
    #{items}
    <p style="color:#999;font-size:12px">You're receiving this because you opted in to digests.
    <a href="#{unsub}">Unsubscribe</a>.</p>
    """
  end

  defp text(user, articles) do
    unsub = url(~p"/digests/unsubscribe/#{Digests.unsubscribe_token(user)}")
    items = Enum.map_join(articles, "\n", fn a -> "- #{a.title}: #{url(~p"/articles/#{a.slug}")}" end)
    "Your Verscienta digest:\n\n#{items}\n\nUnsubscribe: #{unsub}"
  end

  defp esc(s), do: s |> Phoenix.HTML.html_escape() |> Phoenix.HTML.safe_to_string()
end
```

```elixir
defmodule Verscienta.Digests.Workers.SendDigestWorker do
  @moduledoc "Builds + sends one user's digest. Skips off/empty; records last_digest_at."
  use Oban.Worker,
    queue: :default,
    max_attempts: 3,
    unique: [keys: [:user_id], period: 3600, states: Oban.Job.unique_states(:incomplete)]

  alias Verscienta.Accounts.User
  alias Verscienta.Digests
  alias Verscienta.Digests.Email

  @impl Oban.Worker
  def perform(%Oban.Job{args: %{"user_id" => id}}) do
    if Verscienta.Flags.enabled?(:digest_emails), do: send_digest(id), else: :ok
  end

  defp send_digest(id) do
    case Ash.get(User, id, authorize?: false) do
      {:ok, %{digest_frequency: :off}} ->
        :ok

      {:ok, user} ->
        case Digests.highlights(user) do
          [] ->
            :ok

          articles ->
            with {:ok, _} <- Email.deliver(user, articles) do
              user
              |> Ash.Changeset.for_update(:record_digest_sent, %{}, authorize?: false)
              |> Ash.update!()

              :ok
            end
        end

      {:error, _} ->
        :ok
    end
  end
end
```

```elixir
defmodule VerscientaWeb.DigestController do
  use VerscientaWeb, :controller

  alias Verscienta.Accounts.User
  alias Verscienta.Digests

  def unsubscribe(conn, %{"token" => token}) do
    with {:ok, user_id} <- Digests.verify_unsubscribe_token(token),
         {:ok, user} <- Ash.get(User, user_id, authorize?: false) do
      user
      |> Ash.Changeset.for_update(:set_digest_frequency, %{digest_frequency: :off}, authorize?: false)
      |> Ash.update!()

      html(conn, page("You've been unsubscribed", "You will no longer receive Verscienta digest emails."))
    else
      _ -> html(conn, page("Invalid link", "This unsubscribe link is invalid or has expired."))
    end
  end

  defp page(heading, body) do
    """
    <!DOCTYPE html><html><head><meta charset="utf-8"><title>#{heading}</title></head>
    <body style="font-family:sans-serif;max-width:480px;margin:80px auto;padding:0 16px">
    <h1>#{heading}</h1><p>#{body}</p><p><a href="/">Back to Verscienta</a></p>
    </body></html>
    """
  end
end
```

## Notes for the implementer

- **Opt-in by default**: `digest_frequency` defaults to `:off` — no one gets mail until they pick daily/weekly in settings. The worker no-ops for `:off`.
- The worker is **fail-safe + flag-gated**: off flag / off user / missing user / empty highlights all return `:ok` (no send); a deliver error bubbles for Oban retry. `last_digest_at` is recorded only on an actual send.
- **Unsubscribe needs no login** — the signed `Phoenix.Token` carries the user id; the controller sets `:off` with `authorize?: false`. An invalid/expired token renders a friendly 200, never crashes.
- **Email HTML escapes** article title/excerpt (`esc/1`) so author content can't inject markup into the email.
- `highlights/1` reuses `for_you` (already eligibility-filtered + engagement-excluded) and narrows to the frequency window by `published_at`. Empty window → `[]` → no send.
- The scheduled cron that enqueues `SendDigestWorker` per user by frequency is **slice 2** — this slice's worker is enqueued in tests/manually.
- Email tests run with the Swoosh **Test adapter** + `set_swoosh_global` + `async: false`; `SendDigestWorker.perform/1` is called directly (sync) so the delivery lands before the assertion.
