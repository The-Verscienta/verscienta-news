# Moderation Auto-Actions Slice 2 (Shadowban) — Implementation Plan

> **Historical — standalone Verscienta app.** This file describes `Verscienta.*` LiveView work. It is not the Kiln overlay and it is not Slice 1. Current scope is [`docs/slice-1.md`](../../slice-1.md).


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add SHADOW — a silent, author-only-visible shadowban for comments and articles, applied manually by moderators: invisible to everyone except its author (who sees it normally, unaware), audited, and reversible only by explicit unshadow.

**Architecture:** Add a third `moderation_status` value `:shadowed`. Slice 1's global `== :visible` filters already exclude it from every feed/search/rec/room/count, so shadowed content is hidden from everyone for free. The only new work is letting the author still see their own: an Article read-policy tweak (author loads it; public 404s) and a viewer-aware filter on the article-reader's comment thread. Plus the manual moderator action, audit entries, and queue UI.

**Tech Stack:** Elixir, Phoenix LiveView, Ash 3, AshPostgres, Meilisearch.

**Spec:** `docs/superpowers/specs/2026-06-09-moderation-shadow-slice2-design.md`

**Conventions:**
- All `mix` commands run in Docker: `docker compose exec app mix ...` (service `app`).
- Migrations autogenerated via `mix ash_postgres.generate_migrations` — do NOT hand-write. (Widening an `:atom` `one_of` over a `text` column likely produces no DB migration; run it anyway to sync snapshots and apply whatever it makes.)
- Commit messages end with the `Co-Authored-By` trailer shown in each commit step.
- Branch: `phase-3-moderation-shadow` (stacked on Slice 1). Each implementer should `git checkout phase-3-moderation-shadow` first and STOP/report if the tree is dirty.

Change the two comment loaders to take a `viewer_id` and apply a filter. Replace `load_top_comments/1` and `load_top_comment/1` with:

```elixir
  defp load_top_comments(article_id, viewer_id) do
    Comment
    |> Ash.Query.for_read(:list_for_article, %{article_id: article_id})
    |> Ash.Query.load([:user, replies: [:user]])
    |> Ash.read!(authorize?: false)
    |> Enum.filter(&is_nil(&1.parent_id))
    |> visible_to(viewer_id)
  end

  defp load_top_comment(id, viewer_id) do
    Comment
    |> Ash.Query.filter(id == ^id and is_nil(parent_id))
    |> Ash.Query.load([:user, replies: [:user]])
    |> Ash.read_one!(authorize?: false)
    |> case do
      nil -> nil
      comment -> comment |> List.wrap() |> visible_to(viewer_id) |> List.first()
    end
  end

  # Shadowed comments are visible only to their author. Drop others' shadowed
  # comments (and shadowed replies) entirely; the viewer's own shadowed comments
  # render normally.
  defp visible_to(comments, viewer_id) do
    comments
    |> Enum.reject(&shadowed_and_not_owned?(&1, viewer_id))
    |> Enum.map(fn
      %{replies: replies} = c when is_list(replies) ->
        %{c | replies: Enum.reject(replies, &shadowed_and_not_owned?(&1, viewer_id))}

      c ->
        c
    end)
  end

  defp shadowed_and_not_owned?(%{moderation_status: :shadowed, user_id: uid}, viewer_id),
    do: uid != viewer_id

  defp shadowed_and_not_owned?(_comment, _viewer_id), do: false
```

defmodule Verscienta.Moderation.ShadowActionTest do
  use Verscienta.DataCase, async: false

  alias Verscienta.Moderation
  alias Verscienta.Moderation.{Action, Subject}

  defp user(name, role \\ :user) do
    u =
      Verscienta.Accounts.User
      |> Ash.Changeset.for_create(:register_with_password, %{
        email: name <> "@example.com",
        username: name,
        password: "password123",
        password_confirmation: "password123"
      })
      |> Ash.create!(authorize?: false)

    if role == :user do
      u
    else
      u
      |> Ash.Changeset.for_update(:update_profile, %{}, actor: u)
      |> Ash.Changeset.force_change_attribute(:role, role)
      |> Ash.update!(authorize?: false)
    end
  end

  defp comment_with_flag(author) do
    {:ok, art} =
      Verscienta.Content.Article
      |> Ash.Changeset.for_create(:create, %{title: "A", blocks: [], category: :movement},
        actor: author
      )
      |> Ash.create()

    c =
      Verscienta.Engagement.Comment
      |> Ash.Changeset.for_create(:create, %{body: "bad", article_id: art.id}, actor: author)
      |> Ash.create!()

    Moderation.ai_flag(:comment, c.id, :harassment, "toxic")

    author = user("sa_author")
    mod = user("sa_mod", :moderator)
    c = comment_with_flag(author)

    assert :ok = Moderation.apply_manual_action(:shadow, :comment, c.id, mod)

    assert {:error, :unauthorized} = Moderation.apply_manual_action(:shadow, :comment, c.id, plain)

## Notes for the implementer

- **Why shadow is mostly free:** Slice 1's global reads filter `moderation_status == :visible`, which already excludes `:shadowed` everywhere (feeds, search index + fallback, recommendations, room messages, comment counts, sitemap, trending, following). This plan only adds the author-visible exceptions (article read policy + comment-thread filter) and the moderator controls.
- **Held vs shadowed distinction:** a held article is publicly loadable behind an "under review" notice (transparent quarantine); a shadowed article 404s for the public (silent). The read-policy change excludes only `:shadowed` from public reads, never `:held`.
- **Shadow persists:** `resolve/5` lifts holds but is deliberately left untouched for shadow — only an explicit `:unshadow` clears it.
- **Real-time staleness:** shadowing content doesn't broadcast, so an already-open thread/page won't live-update; it filters on next load. Accepted for this slice.
- **Out of scope:** room-message shadow (`Subject.shadow(:room_message, _)` is a no-op), auto-shadow for repeat offenders, and the bookmarked-then-shadowed-article library edge case.
