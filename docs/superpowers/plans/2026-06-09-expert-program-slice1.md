# Expert Program Slice 1 (Application → Review → Role) — Implementation Plan

> **Historical — standalone Verscienta app.** This file describes `Verscienta.*` LiveView work. It is not the Kiln overlay and it is not Slice 1. Current scope is [`docs/slice-1.md`](../../slice-1.md).


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user apply for verified-expert status (statement + credential links), have a moderator/admin approve/reject it in an admin queue, and on approval promote the user to the `:expert` role with an in-app notification and a "Verified Expert" profile badge.

**Architecture:** A new `Verscienta.Experts` Ash domain with an `ExpertApplication` resource (apply/queue/approve/reject). Approval runs through a `Verscienta.Experts.approve/2` context function that stamps the application, promotes the user via a new `User :grant_expert` action (role `:user → :expert`), and creates a notification. A mod/admin-gated `AdminExpertsLive` queue reviews applications; an `ExpertApplyLive` page (flag-gated) lets users apply.

**Tech Stack:** Elixir, Phoenix LiveView, Ash 3, AshPostgres, FunWithFlags.

**Spec:** `docs/superpowers/specs/2026-06-09-expert-program-slice1-design.md`

**Conventions:**
- All `mix` commands run in Docker: `docker compose exec app mix ...` (service `app`).
- Migrations autogenerated via `mix ash_postgres.generate_migrations` — do NOT hand-write.
- Commit messages end with the `Co-Authored-By` trailer shown in each commit step.

defmodule Verscienta.Experts.ExpertApplication.Changes.ValidateApply do
  @moduledoc """
  Before-action checks for `:apply`: the actor must be a plain `:user`, must
  supply at least one http(s) credential URL, and must not already have a
  pending application.
  """
  use Ash.Resource.Change
  require Ash.Query

  @impl true
  def change(changeset, _opts, context) do
    Ash.Changeset.before_action(changeset, &validate(&1, context.actor))
  end

  defp validate(cs, actor) do
    urls = Ash.Changeset.get_attribute(cs, :credential_urls) || []

    cond do
      is_nil(actor) ->
        Ash.Changeset.add_error(cs, field: :user_id, message: "must be signed in to apply")

      actor.role != :user ->
        Ash.Changeset.add_error(cs,
          field: :statement,
          message: "only regular members can apply for expert status"
        )

      urls == [] or not Enum.all?(urls, &valid_url?/1) ->
        Ash.Changeset.add_error(cs,
          field: :credential_urls,
          message: "provide at least one valid http(s) credential URL"
        )

      pending_exists?(actor.id) ->
        Ash.Changeset.add_error(cs,
          field: :statement,
          message: "you already have a pending application"
        )

      true ->
        cs
    end
  end

  defp valid_url?(url) when is_binary(url),
    do: String.starts_with?(url, ["http://", "https://"])

  defp valid_url?(_), do: false

  defp pending_exists?(user_id) do
    Verscienta.Experts.ExpertApplication
    |> Ash.Query.filter(user_id == ^user_id and status == :pending)
    |> Ash.Query.limit(1)
    |> Ash.read!(authorize?: false)
    |> Enum.any?()
  end
end
```

defmodule Verscienta.Experts.ExpertApplication do
  @moduledoc "A user's application for verified-expert status."
  use Ash.Resource,
    otp_app: :verscienta,
    domain: Verscienta.Experts,
    data_layer: AshPostgres.DataLayer,
    authorizers: [Ash.Policy.Authorizer]

  postgres do
    table "expert_applications"
    repo Verscienta.Repo

    custom_indexes do
      index [:status, :inserted_at]
      index [:user_id]
    end
  end

  actions do
    defaults [:read]

    create :apply do
      description "A regular member applies for verified-expert status."
      accept [:statement, :credential_urls]
      change relate_actor(:user)
      change Verscienta.Experts.ExpertApplication.Changes.ValidateApply
    end

    read :queue do
      description "Pending applications, oldest first, for the review queue."
      filter expr(status == :pending)
      prepare build(sort: [inserted_at: :asc], load: [:user])
    end

    read :for_user do
      description "A user's applications, newest first."
      argument :user_id, :uuid, allow_nil?: false
      filter expr(user_id == ^arg(:user_id))
      prepare build(sort: [inserted_at: :desc])
    end

    update :approve do
      description "System/reviewer action: approve the application."
      accept [:reviewer_id]
      require_atomic? false
      change set_attribute(:status, :approved)
      change set_attribute(:reviewed_at, &DateTime.utc_now/0)
    end

    update :reject do
      description "System/reviewer action: reject the application with a note."
      accept [:reviewer_id, :reviewer_note]
      require_atomic? false
      change set_attribute(:status, :rejected)
      change set_attribute(:reviewed_at, &DateTime.utc_now/0)
    end
  end

  policies do
    policy action(:apply) do
      authorize_if actor_present()
    end

    policy action([:approve, :reject]) do
      authorize_if expr(^actor(:role) in [:moderator, :admin])
    end

    # All reads (default :read, :queue, :for_user) are mod/admin-gated. The
    # applicant's own-status read goes through `Experts.latest_for_user/1` with
    # `authorize?: false`, so it doesn't need an actor-scoped read policy here.
    policy action_type(:read) do
      authorize_if expr(^actor(:role) in [:moderator, :admin])
    end
  end

  attributes do
    uuid_primary_key :id

    attribute :statement, :string,
      allow_nil?: false,
      public?: true,
      constraints: [min_length: 20, max_length: 2000]

    attribute :credential_urls, {:array, :string}, allow_nil?: false, public?: true

    attribute :status, :atom,
      allow_nil?: false,
      public?: true,
      default: :pending,
      constraints: [one_of: [:pending, :approved, :rejected]]

    attribute :reviewer_note, :string, allow_nil?: true, public?: true, constraints: [max_length: 1000]
    attribute :reviewed_at, :utc_datetime_usec, allow_nil?: true, public?: true

    create_timestamp :inserted_at
    update_timestamp :updated_at
  end

  relationships do
    belongs_to :user, Verscienta.Accounts.User, allow_nil?: false
    belongs_to :reviewer, Verscienta.Accounts.User, allow_nil?: true
  end
end
```

```elixir
  alias Verscienta.Experts.ExpertApplication

  @doc "Pending applications (oldest first), loaded with the applicant."
  def pending do
    Ash.read!(ExpertApplication, action: :queue, authorize?: false)
  end

  @doc "The user's most recent application, or nil."
  def latest_for_user(user_id) do
    ExpertApplication
    |> Ash.Query.for_read(:for_user, %{user_id: user_id})
    |> Ash.read!(authorize?: false)
    |> List.first()
  end

  @doc """
  Approve an application: stamp it, promote the applicant to `:expert`, and
  notify them. Returns `:ok`, or `{:error, :unauthorized}` if `reviewer` is not
  a mod/admin.
  """
  def approve(application, reviewer) do
    if reviewer.role in [:moderator, :admin] do
      application
      |> Ash.Changeset.for_update(:approve, %{reviewer_id: reviewer.id}, actor: reviewer)
      |> Ash.update!(authorize?: false)

      promote_to_expert(application.user_id, reviewer)
      notify(application.user_id, reviewer.id, :expert_application_approved, %{})
      :ok
    else
      {:error, :unauthorized}
    end
  end

  @doc """
  Reject an application with a reviewer note and notify the applicant. Returns
  `:ok`, or `{:error, :unauthorized}` if `reviewer` is not a mod/admin.
  """
  def reject(application, reviewer, note) do
    if reviewer.role in [:moderator, :admin] do
      application
      |> Ash.Changeset.for_update(:reject, %{reviewer_id: reviewer.id, reviewer_note: note},
        actor: reviewer
      )
      |> Ash.update!(authorize?: false)

      notify(application.user_id, reviewer.id, :expert_application_rejected, %{
        "reviewer_note" => note
      })

      :ok
    else
      {:error, :unauthorized}
    end
  end

  defp promote_to_expert(user_id, reviewer) do
    with {:ok, user} <- Ash.get(Verscienta.Accounts.User, user_id, authorize?: false) do
      user
      |> Ash.Changeset.for_update(:grant_expert, %{}, actor: reviewer)
      |> Ash.update!()
    end

    :ok
  end

  defp notify(recipient_id, actor_id, type, metadata) do
    Verscienta.Notifications.Notification
    |> Ash.Changeset.for_create(:create, %{
      recipient_id: recipient_id,
      actor_id: actor_id,
      type: type,
      subject_type: :user,
      subject_id: to_string(recipient_id),
      metadata: metadata
    })
    |> Ash.create(authorize?: false)

    :ok
  rescue
    _ -> :ok
  end
```

## Notes for the implementer

- **`:expert` role already exists** in `User.role`'s `one_of` — no migration for the value; only the `expert_applications` table is new.
- **`:grant_expert` only promotes a `:user`** (force-change guarded on current role) — it never demotes a mod/admin and is a no-op on an existing expert. It runs `authorize?: false` from `Experts.approve/2` but is also policy-gated to mod/admin for any direct caller.
- **The application row is the audit record** (reviewer_id / reviewed_at / reviewer_note / status). No separate audit-log resource in Slice 1.
- **`Experts.approve/2` / `reject/3` are role-guarded in the context** (mirroring `Moderation.resolve/5`) AND the actions are policy-gated — defense in depth. Notifications are best-effort (never fail the review).
- **Flag gating:** `:expert_program` (seeded OFF) gates the applicant apply form + the settings link. The review queue is mod/admin-gated and simply empty until applications exist.
- **Out of scope (Slice 2):** expert byline labels on articles/comments, `featured_until` + featured placement + feed sorting, experts skipping the moderation hold, expert revocation, email notifications, credential document uploads.
